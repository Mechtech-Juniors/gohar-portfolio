01

CR-01 — AMR Cleaning Robot

in progress

A real autonomous cleaning robot built at SVR Robotics, spanning hardware schematics, ROS2 nodes, and a full operator dashboard. Designed the power tree from 48V LiFePO4 packs through buck converters to the onboard NUC, sensors, and motor drivers, plus EasyEDA schematics for the drive and sensor stack.

Built a multi-page React GUI (login, live map, cleaning schedule, settings) over rosbridge/roslib.js, backed by a Python ROS2 bridge node handling subprocess-based robot launch control. Currently adding teleop, map save/list, and keep-out zone drawing directly on the saved map.

ROS2React/ViteEasyEDArosbridge

Reception Robot — Nav2 Stack (gati_bot)

shipped

End-to-end ROS2 Humble navigation stack for a physical reception AMR: URDF design, AMCL localization, TF2 tree, and costmap tuning, with GIMP-authored keepout masks wired into nav2_params.yaml and lifecycle nodes.

Debug log

Robotics rarely runs first try. Here's what actually got fixed, not the highlight reel.

debug_log.txt
[ERROR] gzserver: zombie process holding simulation port after crash Killed orphaned gzserver processes and added a clean shutdown hook before every relaunch. — reception robot / Gazebo
[ERROR] TF2: use_sim_time mismatch between nodes causing timestamp drops Enforced a single consistent use_sim_time value across every launch file and node. — Nav2 stack
[ERROR] nav2_params.yaml: parse failure from bad indentation in costmap plugin block Rebuilt the YAML block plugin-by-plugin, validating each namespace separator before merging. — keepout filter setup
[ERROR] scan topic mismatch: costmap not receiving LaserScan data Traced remapping through the launch file and aligned the topic name across the driver, URDF, and costmap config. — rplidar / gati_bot
[ERROR] colcon build: package not found despite being in src/ Found the build was running from the wrong workspace root; fixed by always sourcing setup.bash from the correct ws before building. — workspace setup
